## [18.07.2026 10:00] Исследование: диагностика проблем IK-решателя

**Тип:** Исследование / Баг

**Контекст:** IK-решатель увеличивает дисперсию длины костей вместо уменьшения. Стандартное отклонение выросло на 10-90x.

**Что сделано:**
- Написан диагностический скрипт `debug_ik.py`

  1. Абсолютный порог сходимости `1e-4` не масштабируется с реальными единицами (мм)
  2. Gauss-Seidel релаксация осциллирует когда кости разделяют суставы

- Длины костей: от 125мм (ankle-heel) до 480мм (hip-knee)
- Относительная ошибка костей: 5-19%

**Плюсы:**
- Точно определены все три корневые причины

**Минусы / риски:**
- Нет

**Результат теста:** Диагностика завершена

## [18.07.2026 11:00] Решение: убираем кубическую сплайн-интерполяцию, переходим на линейную

**Тип:** Решение

**Контекст:** Кубическая сплайн-интерполяция (`fill_nan_gaps_cubic`) на пропусках длиной 7 кадров создаёт дикие осцилляции (Runge's phenomenon). Дисперсия длины костей после заполнения: 460-3990 вместо 20-41.

**Что сделано:**
- Создана функция `_fill_nan_gaps_linear` в `pipeline.py` — линейная интерполяция через `np.interp`
- Линейная интерполяция гарантированно не выходит за границы опорных точек

**Плюсы:**
- Гарантированно не Overshoot'ит
- Простая и быстрая реализация

**Минусы / риски:**
- Создаёт разрывы скорости на границах пропусков (Butterworth потом это сглаживает)

**Результат теста:** Дисперсия после заполнения: 460-3990 → устранена (не применяется до IK)

**Следующий шаг:** Реорганизация пайплайна

## [18.07.2026 13:00] Решение: FK-BFS вместо итеративной релаксации

**Тип:** Решение

**Контекст:** Итеративная Gauss-Seidel релаксация осциллирует и разошлась на реальных данных. Нужен подход с гарантированной сходимостью.

**Что сделано:**
- Реализован Forward-Kinematics BFS: обход дерева скелета от корней (hips, shoulders) к листьям
- Каждый ребёнок размещается на ТОЧНОМ расстоянии от уже исправленного родителя
- Однопроходный алгоритм, O(n) на кадр, гарантированная сходимость
- Пропуск костей с относительной ошибкой >30% (окклюзия, а не дыхание костей)
- Добавлена передача смещения для нежёстких детей: ankle сдвинулся → heel/foot_index сдвигаются на тот же вектор

**Плюсы:**
- Гарантированно точные длины костей (для исправленных костей std=0)
- Нет осцилляций, нет over-correction
- O(n) по времени

**Минусы / риски:**
- Направление вектора зависит от исходных данных (шумное)
- Зависит от порядка обхода дерева

**Результат теста:** 8/14 костей улучшились (правая рука: +38%, бедро-колено: +59%)

**Следующий шаг:** Передача смещения для нежёстких детей

## [18.07.2026 14:30] Исследование: каталог проблем FreeMoCap — блок 7-14 (аппаратные и системные факторы)

**Тип:** Исследование

**Контекст:** Помимо 6 проблем пост-обработки (jitter, окклюзии, дышащие кости, left/right, скольжение стоп, стыковка сетей), выявлен ряд дополнительных факторов, влияющих на качество данных на этапах до пост-обработки. Эти проблемы связаны с калибровкой, аппаратурой, геометрией съёмки и экспортом.

**Что сделано:** Составлен каталог из 8 дополнительных проблем (№7-14) с описанием механизмов, классических путей решения и направлений для модельных подходов:

**Проблема 7: Точность калибровки камер**
- Механизм: Anipose строит модель камер по калибровочной доске. Ошибка калибровки — систематическая (смещает каждый кадр в одну сторону), не устраняется усреднением.
- Классический путь: пересъёмка калибровки с большим разнообразием ракурсов, жёсткая подложка, равномерное освещение. Reprojection error как ориентир.
- Модельное направление: self-calibration / calibration refinement по данным реальной съёмки постфактум.

**Проблема 8: Рассинхронизация камер по времени**
- Механизм: 6 камер OV9281 — независимые, синхронизация программная по таймстампам. На резком движении кадры могут быть разъехавшимися на 10-30 мс (несколько см смещения).
- Классический путь: аппаратная синхронизация, распределение камер по USB-контроллерам.
- Модельное направление: оценка и компенсация индивидуальной задержки каждой камеры по скорости движения точек.

**Проблема 9: Неравномерная точность по оси глубины**
- Механизм: триангуляция точно определяет положение вбок/вверх-вниз, но хуже вдоль направления взгляда. При кучной расстановке камер слабые оси совпадают.
- Классический путь: равномерная расстановка камер по кругу (45-60° между соседними).
- Модельное направление: адаптивное взвешивание вклада каждой камеры в зависимости от геометрии обзора.

**Проблема 10: Плоскость пола и масштаб не совпадают с реальным миром**
- Механизм: система координат привязана к позиции калибровочной доски, без связи с полом.
- Классический путь: фиксация плоскости пола во время калибровки, ручное выравнивание при экспорте.
- Модельное направление: автоматическая детекция плоскости пола по моментам контакта стопы.

**Проблема 11: Разная экспозиция/яркость между камерами**
- Механизм: каждая камера настраивается по экспозиции независимо. Разброс яркости снижает уверенность MediaPipe.
- Классический путь: ручная проверка и выравнивание экспозиции.
- Модельное направление: программная нормализация яркости/контраста перед подачей в MediaPipe.

**Проблема 12: Ретаргет на скелет с другими пропорциями**
- Механизм: FreeMoCap выдаёт скелет с пропорциями актёра. При переносе на персонажа с другими пропорциями стопа может проваливаться/зависать.
- Классический путь: IK Retargeter в UE5.
- Модельное направление: ретаргетинг с сохранением контактов (стопа-пол, рука-предмет).

**Проблема 13: Лицо и пальцы — низкое качество из общих камер**
- Механизм: MediaPipe Holistic физически ограничен размером лица/рук в кадре при съёмке в полный рост.
- Классический путь: отдельный съёмочный канал крупным планом.
- Модельное направление: специализированные hand-pose сети, обученные на кадрах крупного плана.

**Проблема 14: Пропуск кадров при записи из-за перегрузки USB**
- Механизм: пропуски кадров при перегрузке USB-шины — явные или неявные (таймстампы «уезжают»).
- Классический путь: контроль fps/дропов, распределение камер по портам.
- Модельное направление: детекция скрытого сдвига таймстампов постфактум по несостыковкам в триангуляции.

**Плюсы:**
- Комплексный каталог всех выявленных проблем с разделением на аппаратные и модельные
- Каждая проблема описана с механизмом, классическим решением и модельным направлением
- Открытые формулировки позволяют оценить варианты без предвзятости

**Минусы / риски:**
- Проблемы 7-14 требуют оценки оправданности усилий для конкретного проекта
- Некоторые решение (самокалибровка, компенсация рассинхрона) — исследовательские направления
